# Accessibility Audit
## Purpose
Check keyboard use, labels, focus, contrast cues, state announcements, and reduced motion.
## When to use
Use for new interactive controls, dialogs, voice, and animated visuals.
## Required inputs
Target views and supported interaction paths.
## Permitted tools
DOM inspection, keyboard automation, and accessibility snapshots.
## Prohibited actions
No automated claim of full compliance or content mutation.
## Execution steps
Inspect roles/names, tab order, focus, live regions, and reduced-motion behavior.
## Evidence requirements
Record selector, expected behavior, actual behavior, and severity.
## Output format
Actionable issues and verified passes.
## Validation and rollback
Re-run keyboard and reduced-motion paths after repair.
